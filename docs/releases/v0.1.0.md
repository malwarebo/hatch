First tagged release. `hatch` sandboxes MCP (Model Context Protocol) servers
on Linux and macOS, enforcing per-server network, filesystem, and
protocol-level policies declared in signed manifests.

This is an early `0.x` release. The Rust workspace compiles and tests
cleanly on Linux and macOS CI, but the Linux runtime backend has not yet
been exercised end-to-end on a real host (see Known limitations).

## What ships

**Daemon and CLI**
- Long-running `hatch-daemon` listening on a `0600` unix socket, with
  per-server `hatch-shim` bridging stdio to MCP hosts.
- `hatch` CLI: install / uninstall / list / run / stop / inspect, audit
  viewer (text + `ratatui` TUI), `hatch observe` (syscall trace →
  candidate manifest), `hatch manifest validate|explain|show|diff|edit`,
  `hatch config status|sync|unsync` (with `--workspace` for per-project
  `.cursor/mcp.json`), `hatch registry install-bundle|list|verify`,
  `hatch debug audit-verify`, `hatch debug profile`, `hatch doctor`.

**Manifests**
- TOML schema with capability surface for network (HTTPS SNI + DNS
  allowlist, optional plaintext HTTP), filesystem (read/write/tmpfs/deny),
  env passthrough, resource limits, tool policy (deny patterns + CEL
  rules), response filters, integrity pins (npm/pip/git), and platform
  overrides (`platform.linux.seccomp_preset`, `platform.linux.landlock`,
  `platform.macos.endpoint_security`).
- ed25519 signature verification with a pluggable trust store.

**Sandbox enforcement**
- **Linux**: user/mount/pid/net namespaces, cgroups v2 with explicit
  `cgroup.procs` attach, iptables redirects inside a per-server netns,
  plus a `hatch-linux-helper` pre-exec binary that applies a Landlock
  ruleset and a seccomp-bpf denylist (mount/module/bpf/perf/ptrace/etc.;
  `strict` preset additionally blocks `unshare`, `setns`, `clone3`, the
  new mount-API, and, when subprocesses are disallowed,
  `execve`/`execveat`).
- **macOS**: per-server `sandbox-exec` profile, PF anchor per sandbox UID,
  UID pool managed by `hatch`, `launchd` agent for the daemon.

**Egress**
- SNI-filtering HTTPS proxy (parses TLS ClientHello, matches against the
  manifest's `allow_https`).
- DNS allowlist resolver built on `hickory-proto` 0.26.

**Audit**
- Per-day JSONL with a SHA-256 hash chain. `hatch debug audit-verify
  [--path FILE | --all]` walks the file and reports any chain breakage or
  malformed lines.

**Approvals**
- Three remember modes (`once` / `session` / `manifest-version`).
- Session and manifest-version approvals are persisted to SQLite and
  reloaded on daemon start, so restarts don't drop your prior decisions.
  Deadlines are stored as wall-clock unix seconds.
- Uninstalling a manifest forgets any remembered approvals for that
  server.

**Metrics**
- Prometheus endpoint via `--metrics-addr 127.0.0.1:9876`:
  `hatch_audit_events_total{event_type}`,
  `hatch_audit_write_errors_total`,
  `hatch_tool_calls_total{server,tool,decision}`,
  `hatch_tool_call_latency_seconds{server,tool}`,
  `hatch_approval_latency_seconds{server}`,
  `hatch_net_attempts_total{server,decision}`,
  `hatch_servers_running`, `hatch_servers_spawned_total{server}`,
  `hatch_daemon_uptime_seconds`.

**Host config**
- One-shot rewrite of Claude Desktop, Cursor, Claude Code, Zed, Continue,
  and Windsurf configs to route their MCP servers through `hatch-shim`,
  with reversible backups (`hatch config unsync`).

## Install

This release ships the following artifacts. Verify against `SHA256SUMS`
before installing.

- `hatch_0.1.0-1_amd64.deb`, `hatch_0.1.0-1_arm64.deb`
- `hatch-0.1.0-1.x86_64.rpm`, `hatch-0.1.0-1.aarch64.rpm`
- `hatch-0.1.0-x86_64-unknown-linux-gnu.tar.gz`,
  `hatch-0.1.0-aarch64-unknown-linux-gnu.tar.gz`
- `hatch-0.1.0-universal-apple-darwin.tar.gz` (signed/notarized `.pkg`
  when Apple credentials are supplied to the workflow)

See [`README.md`](https://github.com/malwarebo/hatch/blob/v0.1.0/README.md#install)
for the exact commands. The Linux packages install `hatch`,
`hatch-daemon`, `hatch-shim`, and `hatch-linux-helper` into `/usr/bin/`
plus a systemd user unit at `/usr/lib/systemd/user/hatch-daemon.service`.

## Known limitations

- **Linux backend is not yet exercised end-to-end on a real host.** Every
  Rust path compiles and unit-tests cleanly in CI on `ubuntu-latest`, but
  the namespace + cgroup + iptables wiring and the Landlock + seccomp
  filters applied by `hatch-linux-helper` only run for real on a host
  with kernel 5.13+, user namespaces enabled, and cgroups v2.
- **macOS Endpoint Security** path is scaffolded but gated on the Apple
  ES entitlement, which is not yet granted.
- **macOS notarization** depends on `APPLE_DEVELOPER_ID_APPLICATION`,
  `APPLE_DEVELOPER_ID_INSTALLER`, and `APPLE_NOTARY_PROFILE` being set in
  the release workflow secrets; without them, the macOS artifact is an
  unsigned tarball, not a signed `.pkg`.
- **No release-artifact signatures yet.** Per-asset SHA-256s (in
  `SHA256SUMS`) prove the download wasn't corrupted, but not that
  hatch.dev produced it. minisign / Sigstore signing is on the roadmap.
- **`manifests.hatch.sh`** registry browser is a separate Astro project
  not in this repo. The signed-bundle format, schema, and 20 sample
  manifests under `manifests/` are part of this release.
- **No third-party security audit yet.** Threat model is in
  [`docs/src/concepts/threat-model.md`](https://github.com/malwarebo/hatch/blob/v0.1.0/docs/src/concepts/threat-model.md).
  Use accordingly.

## Compatibility

- First tagged release. No prior public version.
- `schema_version = "1.0"` for manifests; future schema changes will be
  additive within `1.x` and breaking only at `2.0`.
- The IPC wire format between `hatch-cli` / `hatch-shim` / `hatch-daemon`
  is internal and may change between `0.x` releases.

## Verification

Smoke test once installed:

```bash
hatch doctor
hatch debug audit-verify --all   # should print "ok" lines per file
```

Per-asset checksum verification:

```bash
# downloads SHA256SUMS and one or more assets into the same dir
sha256sum -c SHA256SUMS --ignore-missing
```
